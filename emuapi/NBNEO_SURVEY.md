# nbneo-rr as a spec surface

`[SURVEYED 2026-09-04]` — read-only, against `~/dev/anita/nbneo-rr`.

The third host looked at for `docs/lua_api_spec.lua`, after flycast-dojo
(implemented) and fbneo-rr (surveyed). It is the same author's successor to
fbneo-rr and takes deliberate positions against it, which makes it the most
useful surface so far: where it agrees with this spec independently, that is
corroboration; where it disagrees, one of the two is wrong on purpose.

**Read this before acting on it.** nbneo-rr's `script/README.md` is partly
aspirational. Several of its strongest claims are not implemented, and one is
retracted by nbneo-rr's own `docs/FACTS.md`. The split below is the point of
the document, not a caveat on it.

Provenance marks follow `CLAUDE.md` §2. Claims marked `[VERIFIED HERE]` were
re-checked in this repo's session rather than taken from the survey.

## The binding architecture, which decides what an adapter costs

`[MEASURED]` `script/lua_host.cpp` sets two globals from C (`__nb_emit`,
`__nb_quit`, lines 429–432) and then runs a ~350-line **Lua bootstrap string**
(`kBootstrap`, `lua_host.cpp:22–373`) that builds `nb.mem`, `nb.emu`,
`nb.on/off/_dispatch`, `nb.task/wait/wait_for/_pump`, `nb.draw`, `nb.stop`,
`nb.log`. The other `script/lua_*.cpp` files hang sub-tables off the same
global: `nb.input`, `nb.dbg`, `nb.qsnd`, `nb.state`, `nb.step`, `nb.overlay`,
`nb.act`, `nb.observe`.

Everything above that line — `ui`, `observe.*`, `timeline.*`, `transcript`, the
analysis corpus — is **pure Lua reached by `require`**, over ImGui bindings
generated by `dear_bindings` and consumed through LuaJIT FFI.

**Consequence.** An nbneo adapter is cheap in exactly the way flycast's was: a
Lua file wrapping `nb.*` and returning tables, with no C++ change. Host
detection is `rawget(_G, "nb") ~= nil`. `api.install()` would *succeed* there,
where it refuses on fbneo-rr — see D3.

## (A) Better, and implemented — the spec should change

### A1. Drawing legality is a capability object, not a thread-local flag

`[MEASURED]` `script/lua_overlay.cpp:68–82`. A painter is handed a `pane`
stamped with a generation that is bumped on the way out of every paint
(`:441–445`). Stash the pane and use it from a `tick` hook next frame and it
raises:

> `nb.overlay: this pane is only valid inside the painter it was handed to — it
> is a machine's picture in one frame, not a canvas you can keep`

This is strictly stronger than question 6's `thread_local inDrawCallback` flag,
at no extra cost. The flag answers *am I inside a draw callback right now*. The
stamped handle answers *is this the surface I was handed, in the frame I was
handed it* — which also catches keeping the surface across frames, catches
re-entrancy, and needs no thread machinery at all on a single-threaded host.

There is also **no ambient "the screen"**: `pane:size()` returns the emulated
picture's dimensions and `pane:about()` says which machine it belongs to.

**Proposed change.** `gui.register(fn)` passes the surface as an argument and
`gui.*` become methods on it. The existing rule survives as a *consequence*
rather than as something each implementer must remember to enforce, and the
conformance check becomes "hand the painter a stale surface, require a raise",
which is stronger than "call `gui.text` from the wrong callback".

### A2. Tier-2 failure is `nil, reason`

`[MEASURED]` Uniform in nbneo, with the reason stated at each site.
`nb.state.load` distinguishes *not a savestate* / *another game's savestate* /
*corrupt file* — "three different problems, and a caller that collapses them
reports the wrong one". `nb.mem.view` returns `nil, "no such region: %s"`.

Our tier 2 is *absent data returns `nil`*. Bare `nil` is one bit. `nil, why` is
the same bit plus attribution, ignorable by every `if x then` call site, and
free.

**Proposed change.** Tier 2 becomes: *absent data returns `nil` followed by a
reason string. A caller may ignore the second value; a conforming host must
supply it.* Gives the conformance suite a cheap universal check.

### A3. The re-simulation rule has two consumers

`[MEASURED]` `shell/gui/main_gui.cpp:1492–1497`, `:2913–2917`, `:1529–1531`.
During re-simulation nbneo runs **no** `tick` hooks and **no** task pump, but
**does** run `observe_commit_frame`, so the derive graph folds every
re-simulated frame.

Our spec states one rule — frame callbacks are not delivered for re-simulated
frames — which is right for subscribers and wrong for pure functions of state.
Subscribers accumulate, so re-delivery double-counts; derives are required to
be deterministic, so re-running them is the only way to reconstruct a branch.

**Proposed change.** State the rule as a property of the *consumer*: an
accumulating subscriber is not called for re-simulated frames; a declared pure
derive is. Costs flycast-dojo nothing today (it has no derive concept) and
stops the spec being wrong for any host that grows one.

### A4. `generation()` — a version stamp, explicitly not a clock

`[MEASURED]` `nb.state.generation()` is bumped by every successful load and by
nothing else; stepping does not move it. Its docstring is emphatic: *"THE
RETURN VALUE IS A VERSION STAMP, NOT A CLOCK. Compare it for equality; never
subtract two of them, never test it for freshness."*

`frame.confirmed()` answers *how far has confirmed time got*. It cannot answer
*is this still the same machine I have been accumulating over* — the question a
savestate load, a scrub or a replay seek all raise, and which this spec has no
primitive for.

**Proposed change.** Add `emu.generation()` beside `frame.confirmed()`,
documented as equality-only, and make the rollback contract say that an
observer holding state across frames compares the generation, not the frame
number.

### A5. Input as arbitrated claims with provenance

`[MEASURED]` `script/lua_input.cpp:47–110`. `nb.input.claim(key, what, role)`
where `what` ∈ `press | release | **unset**` and `role` ∈ `explicit | standing
| filler`; `nb.input.state(key)` returns `pressed, owner, verdict` with verdict
∈ `ok | displaced | REFUSED`; `nb.input.refused()` returns a count.

Our rule — present-and-true presses, present-and-false releases, **absent
leaves that button alone** — is the same tri-state, reached independently.
That is strong corroboration. nbneo then goes two steps further:

1. The third state is an **explicit value**, not encoded as key-absence.
   Absence-as-a-value does not compose: you cannot build a table of decisions
   where one of them is "I abstain" and hand it to something else.
2. There is a **verdict channel**. Our model gives a script no way to learn
   that its press never reached the machine because another writer won.

The failure it exists to prevent is our own black-AVI shape:

> *"a predecessor probe pressed 'hp P2' for 180 frames, passed its neutral
> control, and reported zero exchanges. It had pressed nothing at all, and
> every downstream check agreed with it."*

**Proposed change.** Keep named booleans. Add an explicit "not speaking for
this button" value and a refusal count, capability-gated for hosts with no
arbiter.

### A6. Memory regions publish size and writability

`[MEASURED]` `nb.mem.regions()` returns `{name, size, read_only}` records, and
`view()` prepends `const` to the ctype when `read_only` — *"the caller cannot
opt out by naming its own ctype, because opting out is exactly the mistake."*

Our `memory.spaces()` returns bare strings and `memory.space(name)` an accessor
with no bounds. nbneo's own `@open` note names what that costs: `prog_opcode`
is shorter than `prog_data`, and indexing past it reads off the end of the
buffer.

**Proposed change.** `memory.spaces()` returns records `{name, size,
writable}`; `memory.space(name)` exposes `.size`.

### A7. Reads inside a painter should be scoped to the state being drawn

`[MEASURED]` `pane:work()` exists because by the time painters run, the shell
has restored the player's state into the one machine — *"so on a live card
`nb.mem` answers about somebody else, correctly and steadily"*.

`[REASONED]` flycast has one machine, so this cannot bite today. But replay
playback and rollback re-simulation are both "the picture on screen is not the
machine in memory". Worth an `[OPEN]` in the spec rather than silence.

## (B) Opinion documented, implementation absent or partial

### B0. Two kinds of "unimplemented", which this survey first ran together

`[REASONED]` **Unbuilt** and **attempted-and-diverged** are different evidence
and were originally filed together under (B).

*Capabilities declared* (B2) is unbuilt: nobody tried, which says nothing about
whether the idea is good.

*Ticks not frames* (B1) is attempted and diverged: the docstring was written,
`tick_from`, the exec hook and the bitmap were built, the derive graph was
wired to ticks — and the scheduler still pumps once per drawn frame. Someone
with full knowledge and full motive did not close that gap, which is far
stronger evidence, and it points at a structural reason.

The likely reason, and the transferable lesson: **a tick is observable but not
schedulable.** Counting ticks from an exec hook costs one load and one branch.
*Resuming script control* there would re-enter the machine mid-instruction —
which is why nbneo refuses `nb.step` from inside a hook — so the pump has
nowhere to live but the frame loop. Observation points and control points are
different sets, and a spec assuming one clock serves both will always have this
gap. Our own `emu.frameadvance` has the same shape: it resumes on the frame
callback because that is the only safe place, not because frames are the right
granularity.

### B1. "`emu` advances ticks, not frames" — the scheduler runs on frames

`[VERIFIED HERE]` The strongest claim in nbneo's README, and it does not hold
of `emu`.

- `nb.wait(n)` is `for _ = 1, (n or 1) do coroutine.yield() end`
  (`lua_host.cpp:260–262`).
- `nb._pump` has exactly **one** caller, `LuaHost::pump_tasks`, called once per
  **drawn frame** (`shell/gui/main_gui.cpp:2917`).

So `nb.wait(12)` waits 12 drawn frames, while its own docstring says *"a script
that waits on frames cannot land on a tick that was computed and never drawn"*
— a statement about a defect the function does not avoid. `nb.emu.tick_bound`
is false by default, and while false `nb.emu.tick` **mirrors the frame count**.
Only `nb.dbg.tick_from(addr)` binds a real tick, and the address is the
script's to supply.

The derive side *is* tick-granular; the claim is true of `observe/` and false
of `emu` and the scheduler.

**What to take.** Not the clock. The tick is not discoverable from the
emulator — it is a ROM address supplied by a script — and nbneo's own scheduler
did not manage to run on it. What is portable is the **honesty requirement**: a
host publishing a counter must say what it counts. The underlying measurement
is real and worth recording: `core/compat/exec_hook.cpp:8–13` — VSAV computes
1–2 logic ticks per displayed frame, and *"the same 24-tick slide was recorded
as 23 in one run and 24 in another purely from where frame boundaries fell."*

### B2. "Capabilities are declared, not discovered" — no implementation

`[MEASURED]` `script/README.md:110` and `PLAN.md:374` §4.7 argue this at
length. A grep for `capabilit`, `require_caps`, `caps =` across `script/`,
`lua/`, `observe/`, `timeline/`, `shell/` returns **zero** declaration or
enforcement sites. There is no manifest, no `declare{}`, no runtime refusal.
The `nb.act` gate system is a *hotkey* gate, and `nb.act.fire` bypasses it.

**CORRECTION 2026-09-05.** Declining the *replacement claim* was right;
letting that decline carry the *mechanism* with it was not. flycast-dojo's
largest open feature is exactly a declaration system — Lua is refused entirely
when online (`core/nullDC.cpp`), and the fix in `TODOS.md` is OFF / OBSERVER /
MUTATOR / FULL tiers. We need declaration for our own reasons, and its place in
the spec should never have been contingent on whether nbneo built theirs.

`emu.declare{tier=}` / `emu.tier()` are now in the spec and implemented in
`emuapi.lua`, enforced by wrapping the namespaces after the adapter builds them
— so an adapter needs no knowledge of tiers to be governed by them. The two
mechanisms are stated as orthogonal: `supports()` is portability, `declare()`
is authorisation.

**Keep `emu.supports()`.** The critique of the old one-bit `SpecIsResim()` is
sound, but it is separately answered by two mechanisms that do exist
(`nb.state.generation()`, and `FRAME_PLAYER` vs `FRAME_BORROWED`). Declaration
and discovery are not alternatives anyway: declaration is *authorisation* (may
this script write the timeline?), discovery is *portability* (does this host
have `ui.BeginTable`?). nbneo conflates them in prose and implements neither.

### B3. Hot reload — detection yes, backfill no

`[MEASURED]` Implemented: `derive_version`, `g:versions()`,
`g:changed_since(prev)`, file-level reload with accumulators that survive it.
Not implemented, and said so in-tree at `observe/graph.lua:333–336`: *"This is
the DETECTION half of hot reload; the backfill half needs a parent walk
`timeline/` has no code for and is `[OPEN]`."*

### B4. "Every surface substitutable from Lua" — never exercised

`[MEASURED]` The constraint is visible in the code (the bootstrap is Lua so
every table is overwritable; the pane metatable's `__index` is a plain table).
But `tests/lua/` achieves emulator-independence by **injecting readers and
reading fixture blobs**, not by stubbing — a grep for `nb =` across
`tests/lua/*.lua` returns nothing. Suite `[MEASURED 2026-09-04]`: 27 specs, 416
tests, 27,653 assertions, exit 0, no ROM. Good suite; different technique from
the stated property, which has therefore never been made to fail.

`lua/lib/ui.lua` is admitted non-substitutable: it mutates `package.path` at
load time and calls into the FFI.

### B5. The timeline — spine live, version-controlled machine not

`[MEASURED]` `timeline/timeline.lua` (1,149 lines) implements node identity,
refs, reachability GC, bounded ancestor walk, blob residency. Not built, per
its own README banner: the branch scheduler, the N-branch live view, the
delta-encoded blob arena, persistence, and `diff`. `net/` contains **one file,
a README** — no netplay, no rollback session. There is no `nb.time`; the
`time` module in the README's table does not exist.

### B6. Fault isolation — implemented, and better than claimed

`[MEASURED]` `nb._dispatch` (`lua_host.cpp:196–205`) pcalls, reports, and the
subscriber **stays registered and runs again next tick**. The README says
"disabled for that tick"; it is not disabled at all. Tasks are the exception
and are dropped, which is forced — an errored coroutine is dead.

**This settles open question 7 in nbneo's favour.** Two hosts now independently
agree: register returns a handle, unregister takes one, multiple subscribers is
the normal case, a throwing subscriber is contained rather than evicted.

And it adds something neither this spec nor fbneo-rr has: **ownership**. Every
hook, task and painter carries the path of the file that registered it, stamped
at load time; a coroutine inherits its creator's. `nb.stop(owner)` returns
counts — *"because 'stopped' and 'stopped nothing' are different outcomes"* —
and `nb.owners()` enumerates.

## (C) Absent entirely — what conforming would cost

| spec surface | nbneo status |
|---|---|
| `emu.supports` / `emu.apiversion` | **absent**. The biggest single cost: partial conformance *requires* it |
| `emu.isonline` / `isreplay` / `isrollback` | absent — no netplay exists |
| `frame.confirmed` / `frame.resimsteps` | absent |
| `emu.romname` / `gamename` / `screenwidth` / `screenheight` | absent from Lua |
| `emu.message` | absent (`nb.log` goes to stdout and a console sink) |
| `emu.pause` / `unpause` | only as a hotkey **toggle**, so not idempotent |
| `emu.speedmode` | absent from Lua |
| `emu.frameadvance` / `emu.run` | absent as a yield; `nb.step(n)` is imperative |
| `savestate.save(slot)` / `load(slot)` | **no slot concept in Lua** — paths and blobs only |
| `movie.*` | absent from Lua (`.nbmc` macros are C++/panel-driven) |
| `joypad.getaxis` / `setaxis` | absent — CPS2 has no analog controls |
| `gui.scale` | absent, deliberately |
| `sound.*` | present but QSound-specific, and richer than the spec |

`[REASONED]` Roughly 12 of the 51 non-`ui` names are unreachable at any price
today, ~8 need a shim with a semantic gap, ~30 map cleanly.

## (D) Implemented, and conflicts

### D1. Colour packing — **addressed 2026-09-04**

nbneo packs `0xRRGGBBAA` (`lua_overlay.cpp:84–85`), deliberately, so its
existing corpus of constants keeps meaning what it meant. This spec packs
`0xAABBGGRR` (ImGui's IM_COL32).

`[VERIFIED HERE]` The two agree on exactly the colours a person tests with
first: every grey, **and opaque red** — `0xFF0000FF` is opaque red under both.
They disagree on green and blue.

**Resolved** by `gui.rgba(r, g, b, a)`: channels in, packing hidden, and no
portable script writes a packed literal. The conformance suite now asserts the
packing with green and blue. A control run against a deliberately `0xRRGGBBAA`
implementation was caught by **2 of 3** colour assertions — green and blue
caught it, red did not, which is the whole argument in one line.

### D2. Exec hooks — **exclusion re-opened 2026-09-04**

`[VERIFIED HERE]` The spec excluded `memory.registerexec` because trap-opcode
patching is snapshotted and restored under rollback and desyncs against a peer.
`core/compat/exec_hook.cpp` patches nothing: it rides the m68k PC-changed
callback the core already has, dispatching through a 1 MiB bitmap over the
24-bit address space. Nothing is written into emulated memory. Cost with no
hooks: one load and one branch.

The exclusion was an argument against one *mechanism* promoted into a rule
against the *capability*. Now capability-gated — a recompiler host answers
false, which is what the gate is for.

Also worth stealing from that file: `exec_hook.cpp:101–115` handles
mutation-during-dispatch with mark-dead plus a deferred sweep, where
`EventManager` here copies the listener list. Both are correct; theirs avoids
the copy in a path that runs tens of millions of times a second.

### D3. One installed global `nb`, not returned namespaces

`[MEASURED]` `nb` is a global; every binder hangs a field off it. The pure Lua
layer does follow our shape (`local x = require 'y'`).

Our justification for refusing installation — fbneo-rr already owns `emu`,
`memory`, `input`, `joypad`, `savestate`, `movie`, `gui` — is an argument
against installing **ten common words**, not against **one reserved token**.

**Proposed change.** Permit a single-root install (`api.installAs("emuapi")` →
`emuapi.emu.pause()`) as a documented middle option. "Refuses rather than
clobbers" survives unchanged.

### D4. `ui.*` is not gated to draw callbacks

`[MEASURED]` `lua/lib/ui.lua` has no frame guard; the gating is documentation
only. It cannot cheaply have one: `ui.*` is ~788 generated FFI functions
reached through a metatable fall-through to `ui.C`.

**Proposed change.** State in the spec that the gate belongs to whichever layer
the script calls, and that a host exposing a raw toolkit namespace alongside
the gated one has not conformed for scripts using the raw one.

### D5. Blob byte offsets are 0-based — **addressed 2026-09-04**

`nb.state.regions().offset` is 0-based, with the slice form given. Defensible —
an offset into a byte buffer is an address, not an index — but our rule said
"every index" without qualification. The spec now distinguishes indices
(1-based) from byte offsets into an opaque blob (0-based).

## The usage census, and what it says about this spec

`[MEASURED 2026-09-04]` `tools/lua-census.py` over 583 files of the phobos
corpus, comments lexed out, aliases folded: 413 callable names, 186 never
called (53%), 6,195 call sites, top five are 73% of them.

Uncomfortable readings for `LUA_TODO.md`'s port list:

- All of `movie.*`: **0 call sites**. All of `sound.*`: **0**.
- Five of the twenty mandatory `ui.*` baseline names: **0**. Five more: **1**.
- The entire `joypad.*` namespace — this spec's self-declared *"largest single
  conformance cost"* — **29**.
- `memory.registerexec`, which the spec excluded: **29** (+3 aliased).
- `emu.frameadvance`, which flycast-dojo has: **165**, the third-busiest verb.

`[MEASURED]` The figures in nbneo's `script/README.md` (191 never called,
`memory.readbyte` 1343) are a superseded 2026-08-10 run; the tool's own header
says so. Cite the tool, not the README.

## Provenance warning to carry forward

`[MEASURED]` nbneo-rr's `docs/FACTS.md` §2.3 marks its own most-quoted claim
`[OPEN]`: *"the 30,397-line test suite makes zero emulator calls"* appears in
six files, **every one marked `[MEASURED]`**, none naming what was counted, and
it could not be reproduced (31,065 / 101 / 8,865 on three plausible
denominators). The zero-calls half — the load-bearing part — is `[OPEN]` too.

That is a project's own record catching the failure `CLAUDE.md` §2 exists for,
in a claim repeated confidently across six files. Do not restate either half
without re-deriving it.

## Licensing

`[MEASURED]` There is **no LICENSE file anywhere** in nbneo-rr (excluding
`third_party/`). `README.md:325–331`: *"Emulation core derived from FinalBurn
Neo. CPS2 hardware logic, Musashi m68k, Z80 and the QSound HLE are ported from
it and carry its licence."* `core/` is 42 translation units of FBNeo lineage.

1. **nbneo-rr as a whole is not GPL-compatible**, for the same reason
   fbneo-rr is not. It cannot be combined into flycast-dojo.
2. `script/`, `lua/`, `observe/`, `timeline/` appear independently authored,
   but with **no repository licence at all** their status is all-rights-reserved
   by default. Do not transcribe from them either — on that basis rather than
   FBNeo's.
3. **This document is safe**: observed API surface, behaviour and rationale,
   which is the same footing as the existing note in `docs/lua_api_spec.lua`.
4. If code is ever to move, nbneo-rr needs an explicit licence for its
   non-`core/` directories. The two things most worth reimplementing
   independently — the ImGui FFI generator and the pane-capability overlay
   design — are both outside `core/`.
