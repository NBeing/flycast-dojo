`replay-bindings.flyr` — a 190-frame MvC2 movie used as the load fixture for
`scripts/replay-bindings-test.sh`. Generated by running
`scripts/lua/replay-bindings.lua` in a Just Play session, which calls
`flycast.replay.startRecording()` / `stopRecording()`.

It is 109 bytes of header + 190 × 28-byte frames = 5429 bytes, and those 190
frames are one full `FRAME_BATCH` (120) plus a 70-frame tail that only exists
because `stopRecording` calls `FlushReplay`. That is the file's second job: if
the flush ever regresses it is 120 frames, 3360 bytes, and the size check in the
test fails.

It does NOT start at power-on (Lua began recording mid-session), so playing it
from the top ends immediately with "replay end at frame 0 (no frame data)".
That is expected and is what the mid-session NOTICE_LOG in `lua.cpp` warns about.
